# UI

Дизайн-система и структура веб-интерфейса control plane (D93). Спецификация — код в `ui/`, этот файл — сводка правил, по которым он написан.

Сайт живёт на основном домене, control plane — на поддомене `dash.`.

## Принципы

- **Minimal & polished.** Рабочие экраны тихие: ничего, что тормозит работу. Красота — только на сайте и экране входа.
- **Цифры, а не фразы.** Сводка — числами, без предложений, которые их пересказывают.
- **Честные данные.** Экран показывает только то, что есть в системе. Нет данных — нет элемента.
- **Одно главное действие** на экране — залитая кнопка. Остальные — текстовые ссылки или контурные кнопки.
- **Состояние — словом и цветом.** Цвет никогда не единственный носитель смысла.

## Цвет

- **Оранжевый** — только «живое или ждёт тебя»: идущий Run, непрочитанное, задача в `needs_human`, главная кнопка.
- **Красный** — только сбой или отказ: stuck, deny в Journal, ошибка Run.
- Остальное — оттенки одной тёплой гаммы.
- **Цвет агента** (D101): оператор выбирает оттенок (hue) ползунком, светлоту под каждую тему задаёт UI, поэтому имя читается в обеих. Любой оттенок, оранжевый тоже. Цветом окрашены кольцо и имя агента, а состояние — всегда точкой на кольце и словом (оранжевая — работает, красная — stuck), поэтому цвет агента с состоянием не путается. В карточке хранится одно число, `hue`; без него Registry выводит оттенок из alias.

## Как называть

- Оператор в записях (Journal, история задачи, таблицы) — `@alias`, в разговоре (чат, карта) — «you».
- Права агента показываются группами, а не инструментами: Read files (`read`, `ls`, `grep`, `find`), Write files (`write`, `edit`), Shell (`bash`), Tasks (`task_*`), Send messages (`send_message`). Чтение своих сообщений не выдаётся отдельно: оно есть у каждого агента (D94).
- Ответ оператора на задачу в `needs_human` — сообщение assignee с `task_id`: заметка к задаче агента не будит.

## Типографика

- **Sora** — текст и заголовки. В приложении: 13 px основной, 15 px заголовок экрана, 600 для заголовков панелей. На сайте: 15–17 px текст, заголовки 300.
- **JetBrains Mono** — данные: id, время, пути, статусы, имена инструментов.

## Форма

- Скругление 4 px — только у интерактивного: кнопки, поля, переключатели. Панели, таблицы и чипы — с прямыми углами.
- Поверхности плоские, разделители — линии в 1 px. Тень есть только у главной кнопки на сайте и на входе.
- Агент — кольцо (мотив логотипа). Состояние различается и формой: работает — сплошное, stuck — разорванное, триггер — квадрат.

## Изображения

- Сайт и вход: в тёмной теме — цифровой портрет, в светлой — фото с плёночным зерном.
- Рабочие экраны — без картинок и без зерна.

## Структура

```text
Overview
Triggers
Agents
  Registry
  Messages
  Journal
Tasks
Storage
Integrations
  Providers
  Tools
  MCP
Settings          внизу меню, над alias оператора
```

- **Overview** — сводка числами, карта агентов (только реальные данные: состояние, задача, число сообщений), «Needs you», идущие Run.
- **Messages** — агенты, треды выбранного агента, один тред (D105). Тред — сессия Pi, цепочка или задача (D78): агент помнит только то, что сказано в ней. Ответ идёт в открытый тред, «New thread» начинает новую цепочку. Сообщения агента — Markdown без HTML и картинок.
- **Journal** — действия агентов с фильтрами по агенту, цепочке, задаче и решению Gateway.
- **Tasks** — таблица задач; строка открывает страницу задачи: таймлайн Run и сообщений по участникам, история таблицей, детали, заметка.
- **Вход** — продолжение сайта: та же сетка, форма встаёт на место заголовка. Пока сайта нет, на входе только логотип.

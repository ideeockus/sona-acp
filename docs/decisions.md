# Решения и договорённости

Журнал архитектурных решений Agent Control Plane. Описание системы — в [spec.md](spec.md).
Если они расходятся, действует этот файл.

**Правило проекта:** любое техническое решение, включая выбор crate'ов и форматов, проходит через владельца. Агент готовит варианты с плюсами и минусами, но не выбирает сам. Проект строится как minimal и polished: одна технология на задачу, без «на всякий случай».

**Код — это и есть спецификация.** Владелец читает, ревьюит и может писать его сам, поэтому код держим таким же minimal и polished, как этот документ. Временные упрощения помечаем комментарием в коде.

Статусы:

- **Принято** — владелец подтвердил, можно реализовывать.
- **Склоняемся** — направление согласовано, нужно финальное «ок».
- **Открыто** — не решено, реализовывать нельзя.

Последнее обновление: 2026-11-08.

## Термины

- **Run** — один запуск Pi-процесса для агента: от триггера до `agent_settled` и выхода процесса.
- **run_id** — идентификатор Run, его выдаёт Agent Runtime.
- **Сессия Pi** — история разговора, сохранённая в файл. Живёт дольше Run.
- **Цепочка** — Run'ы, причинно связанные пробуждениями. Начинается действием оператора, срабатыванием Scheduler или внешним событием.
- **correlation_id** — сквозной идентификатор цепочки.
- **Agent Journal** — журнал действий агентов, аналог auditd. Не путать с логами сервисов.
- **Коннектор** — внешняя возможность, которую подключает оператор: MCP-сервер, SSH, пользовательский код. Состоит из capability (что можно делать), scope (над чем) и credential (секрет, хранится только в control plane).
- **Agent Runtime** — компонент, который управляет Run'ами: жизненный цикл, токены, сессии, лимиты, пробуждения. Контейнеры — деталь его launcher'а.
- **Оператор** — человек, управляющий системой (пока владелец проекта).

## Ценность и гипотезы

- Sona разделяет идентичность, контекст, полномочия и выполнение задачи. Упор — безопасность: минимум прав, изоляция, аудит, секреты вне контекста модели.
- **Гипотеза H1:** Manager работает как attention firewall — фильтрует работу исполнителей и отдаёт оператору результат, а не переписку. Проверяем на dogfooding.

## Факты о Pi 1.0.0

Источник — документация и код установленного пакета. Пункты с пометкой **[спайк]** проверены вживую 2026-11-08, подробности — в `spike/README.md` (каталог спайка вне репозитория).

**Проверено в спайке**

- **[спайк]** RPC: `prompt` → события → `agent_settled`. Закрытие stdin завершает процесс с кодом 0.
- **[спайк]** `--tools` объявляет модели ровно перечисленные инструменты, включая custom.
- **[спайк]** С `--system-prompt` и `--append-system-prompt` промпт состоит из нашего текста, `<addendum>` и `<cwd>`.
- **[спайк]** Блокировка в hook приходит модели как ошибочный tool result с нашим `reason`.
- **[спайк]** `--session-id` с тем же id продолжает историю. `steer` доставляется после текущего хода.
- **[спайк]** `baseUrl` в `models.json` перенаправляет запросы — путь для заглушки в тестах (D25) и прокси ключа (O22).
- **[спайк]** `PI_CODING_AGENT_DIR` и `HOME` держат все файлы Pi внутри заданных каталогов.
- **[спайк]** Пиковый RSS процесса Pi — 110–155 МБ с заглушкой модели.
- **[спайк]** `abort` обрывает зависший запрос к модели, приходит `agent_settled`, в сессии остаётся `stopReason: "aborted"`.
- **[спайк]** В сессии у каждого ответа модели записаны `usage` и `cost` (O28).
- **[спайк]** MCP и codemode — встроенные расширения `builtin:mcp` и `builtin:codemode`. `--no-extensions` отключает оба. `-ne -e builtin:mcp` даёт MCP без codemode.
- **[спайк]** MCP-сервер с `exposure: "direct"` запускается при старте сессии, даже если его инструментов нет в `--tools`. С `exposure: "codemode"` в коротком Run процесс не стартовал: такие серверы подключаются по необходимости. Поэтому в конфиг Run должны попадать только выданные агенту серверы.
- **[спайк]** Hook видит и блокирует вызовы MCP-инструментов: сервер вызова не получает.
- **[спайк]** В контейнере (`docker run -i`, образ на `node:22-slim`) RPC, hook и сессии работают так же. Контейнер — 70–83 МиБ после Run, старт на ~1,3 с дольше локального.
- **[спайк]** Сессия Pi привязана к `cwd`: тот же `--session-id` из другого каталога создаёт новую сессию. Workdir в среде агента всегда монтируется по одному пути (`/work`).

**Hooks и tools**

- Обработчик `tool_call` асинхронный, Pi его дожидается. Может вернуть `{ block: true, reason }` или изменить `input`. В событии есть `toolCallId`, `toolName`, `input` и `parentToolCallId`.
- Hook видит встроенные, custom и MCP tools, а также вложенные вызовы из `codemode`.
- Если обработчик `tool_call` упал, вызов блокируется.

**Режимы и RPC**

- `--mode json` — однократный запуск, события в stdout. `--mode rpc` — долгоживущий процесс: JSONL через stdin/stdout. SDK — работа внутри процесса.
- RPC-команды: `prompt`, `steer` (после tool calls текущего хода), `follow_up` (после завершения работы), `abort`.

**Сессии**

- `--session-id <id>` открывает сессию или создаёт её, если такой нет. `--session-dir` задаёт хранилище, `--no-session` держит сессию только в памяти.

**Промпт и skills**

- `--system-prompt` заменяет вводную часть и секции `tools`, `rules`, `docs` стандартного промпта. Секции `addendum` (`--append-system-prompt`), `project_context`, `skills` и `cwd` сохраняются.
- Описания skills попадают в промпт, только если активен `read` или `bash`. Текст `SKILL.md` модель читает сама.
- Изменения секций промпта Pi дописывает в сессию как дельту.

**MCP и codemode**

- MCP встроен. По умолчанию `exposure` у MCP-сервера равен `codemode`, и при подключении такого сервера Pi сам активирует инструмент `codemode`. Отключается через `autoEnableCodemode: false`.
- `pi.registerMcpServer()` подключает MCP-сервер из расширения на текущую сессию.
- Скрипты `codemode` выполняются в QuickJS и выходят наружу через tools и глобальный объект `models`. `models` запускает не-LLM модели с credentials сессии и в список tools не входит.

**Загрузка и безопасность**

- Загрузкой управляют флаги `--tools`, `--no-extensions -e <path>`, `--skill`, `--no-skills`, `--no-context-files`, `--no-approve`.
- `models.json` позволяет переопределить `baseUrl` и заголовки встроенного провайдера. Это путь для прокси ключа (O22).
- Встроенной песочницы нет. Проверка в hook — не граница безопасности на уровне ОС.
